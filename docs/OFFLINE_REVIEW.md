# 多投标文件离线审查口径

## 当前结论

`bqc review-bids` 和 Web 页面 `/review-bids` 只做本地文件的相似性与报价模式预警。
输出固定带有 `manual_review_required=true` 和“自动结论=false”；程序不访问网络、不上传资料、
不修改输入文件，也不输出“串通投标成立”“违法”“资格不合格”或“投标无效”等自动结论。

Web `/review-bids` 的“输入目录”和“关联线索文件”均指运行 Web 服务的服务端所在机器上的本地路径；
该页面无账号鉴权，默认只监听回环地址，且路径默认限制在服务当前工作目录内；设置
`BQC_REVIEW_ROOT` 可指定其他允许目录。`bqc serve --allow-lan` 会显式允许非回环监听，
仅适合可信网络临时使用，不应把含企业资料的目录暴露给不受信任的网络。

当前支持：`txt`、`md`、`csv`、`json`、`xlsx`、`pdf`（文本层与本机 OCR）。当前不解析：`xls`、`docx`。
txt/md/csv/json 文本按 UTF-8（含 BOM）、带 BOM 的 UTF-16 或 GB18030 解码；
无 BOM 的 UTF-16 不作猜测（GBK 等遗留编码按 GB18030 兜底，避免整文件乱码且无提示）。

PDF 逐页读取；无文本、含图像或 Form 内容的页面尝试本机 OCR，结果保留页码和 `extraction_method`。
页眉有文字的扫描页面仍会尝试 OCR。文件采用流式 SHA-256，原始文件保持不变；完整 OCR 文本不写入公开报告。
同页独立报价标签与紧邻的单个金额可识别，不跨页或多个裸数字猜测。
「（¥ 金额）的投标总报价」句式中金额在标签之前，同样可识别，并支持「万元/亿元」后缀换算；
金额前后紧邻保证金/单价/合价/费率/税率/税额等属主名词（如「投标保证金 50000 元」）、
紧邻工期词语（含「N 天内完工」），或被 OCR 断开成多段数字/小数
（如「¥ 797 965 59.18」「¥ 79796559. 18」「1, 234.56」）时一律不猜，宁可漏报。
纵排汇总（标签独占一行、金额在下一非空行）与转置汇总（标签行 + 数值行）按位置一一配对；
数值行之后紧跟数字列、下一行带税率/百分比语义或多个数字时一律放弃配对，宁可漏报，
配对证据同时保留标签行与金额行原文及行号。

PDF 限额：600 MB、2000 页、1000 万文本字符；每份最多尝试 OCR 50 页，累计 120 秒，每页最多 30 秒。
达到上限、提取失败或无法识别时，页级状态及文件标记 `PARTIAL`，报告列出缺口。
部分解析文件保留已识别报价，但不参与全文相似度比较；已识别主报价不代表已排除未读页的冲突报价。
OCR 结果只供人工复核，尤其须核对金额小数点、单位、表格列归属和漏字。

Windows/Mac 发布构建设置 `BQC_BUNDLE_OCR=1`，将识别引擎及中英文语言包纳入可执行文件；
发布前运行 `scripts/smoke_ocr.py`，清空外部工具 PATH 并指向不存在的外部语言目录，验证内置扫描件识别。
构建需用 `BQC_TESSDATA_PREFIX` 指向包含 `chi_sim.traineddata`、`eng.traineddata` 的目录；缺引擎或语言包时构建失败。
macOS 构建还会复制并重写 Homebrew OCR 的非系统动态库加载路径，避免用户必须安装 Homebrew。
源码/Python 安装方式需自行准备外部工具。Mac 已安装 Homebrew 时执行：

```sh
brew install poppler tesseract tesseract-lang
pdftoppm -v
tesseract --list-langs
```

Windows 源码运行时，安装 Poppler 和 Tesseract 后，将包含 `pdftoppm.exe` 与 `tesseract.exe` 的目录加入 PATH；
`tesseract --list-langs` 须列出 `chi_sim` 和 `eng`。图形启动的应用也须继承该 PATH。
依赖缺失时文本页仍可读，需要 OCR 的页面明确提示缺口。OCR 全程本地运行，不上传文件。
开发环境可设置 `BQC_RUN_OCR_TEST=1` 后运行 `pytest tests/test_pdf_ocr.py -q`，验证实际中文引擎；
默认回归不依赖外部 OCR 安装，使用模拟结果验证缺失、超时、预算、页码和脱敏路径。

目录约定：一级子目录名为投标人；根目录文件可用 `投标人名称__文件名.ext`，
无前缀的根目录文件归入根目录名对应的单一投标人，不按文件名拆分。
作为
`--relations` 传入的 CSV/JSON 若位于输入目录内，会被排除在投标文件扫描之外，并单独保留
文件路径、大小、SHA-256、行号和原始字段。关联线索文件的格式歧义（如 CSV 重复表头、
JSON 非对象行）会写入 `parse_warnings` 提示人工核对。

清单项只有在名称、单位和规格/项目特征都存在且一致时才参与跨投标人对齐；缺少任一字段的
明细会保留在 JSON 中并标记为 `INSUFFICIENT_DATA`，不按名称自动合并，也不做单位换算。JSON
中的 `total`/`bid_price` 若是包含金额、币种等字段的复合对象，只继续递归检查，不把对象字符串
当作报价数字；JSON 递归受最大深度 100、最大节点数 100000 限制。扫描会跳过并记录符号链接，
并对输入文件数量、总字节数、XLSX ZIP 成员数、声明解压大小及第二次 XLSX 审计读取的单元格数
设置上限；触发上限时结果会标记扫描截断和未纳入资料。

## 预警信号

| 代码 | 观察内容 | 主要人工复核材料 |
|---|---|---|
| F-01 `QUOTE_NEAR_MATCH` | 主报价相对差异不超过 0.5% | 招标控制价、清单版本、税率、四舍五入、报价编制过程 |
| F-02 `QUOTE_LOW_DISPERSION` | 至少三家报价变异系数不超过 1% | 全部报价、控制价、市场询价和异常低价审查记录 |
| F-03 `QUOTE_OUTLIER` | 单家报价与中位数相对差异达到 10% | 方案范围、工程量、计价口径、澄清答疑及弃标/陪标解释 |
| F-04 `SYNCHRONIZED_LINE_ITEMS` | 在名称、单位、规格/项目特征均可比的前提下，至少三个共有清单项金额接近，或多项报价比例高度稳定 | 原始清单、单位、数量、单价/合价、版本和编制底稿 |
| F-05 `QUOTE_ARITHMETIC_PATTERN` | 至少三家主报价排序后呈近似等差或等比排列；等差相邻差值 CV ≤ 5%，等比相邻比值 CV ≤ 2% | 全部原始报价、控制价、取整规则、报价策略和编制过程 |
| F-06 `UNIFORM_DISCOUNT_RATE` | 至少两家均识别到 `kind=control` 的控制价，且相对控制价下浮率极差 ≤ 0.10 个百分点 | 控制价发布文件、含税口径、取整规则、报价编制底稿和平台留痕 |
| F-07 `QUOTE_NEAR_BAND` | 两家主报价相对差异落在 0.5%~2% 的接近带（真实陪标报价常见区间；≤0.5% 已由 F-01 以「高」级覆盖，本规则补中间带） | 全部主报价、控制价与清单构成、取费/让利口径、取整规则和陪标/弃标解释 |
| E-01 `METADATA_MATCH` | 作者、机器码、MAC、IP、硬盘序列号或数字证书等电子字段相同；人员字段不归入本规则 | 电子招标平台原始日志、数字证书、设备和账号使用记录 |
| E-02 `PAYMENT_ACCOUNT_MATCH` | 投标资料中的银行/保证金/退款账户字段出现相同值；仅作同账户转出风险线索，不等同于《实施条例》第40条第6项事实 | 保证金转出凭证、收付款主体、平台流水、代理代缴授权和原始文件 |
| S-01 `TEXT_EXACT_MATCH` | 可比较文本达到 80 字符且文件字节或去空白文本内容一致 | 招标文件统一模板、固定条款、文件形成时间和编辑痕迹 |
| S-02 `TEXT_HIGH_SIMILARITY` | 同类型文件文本相似度达到 92% | 招标文件统一模板、固定条款、文件形成时间和编辑痕迹 |
| S-03 `STRUCTURE_SIMILARITY` | 文件名/类型组合高度相似 | 投标文件目录、导出批次、模板下发和归档记录 |
| S-04 `LINE_ITEM_SET_MATCH` | 至少 8 个 `COMPARABLE` 清单项的 `comparison_key` 交并比达到 90%，即使金额不同也提示 | 招标清单版本、名称、单位、规格/特征、导出和编制记录 |
| S-05 `SHARED_TEXT_BLOCKS` | 文件去空白文本按 200 字定长分块后，两家共有至少 3 个相同块且占较小一方块数 10% 以上（抓整文比对漏掉的大段共用文本）；块内容不写入证据 | 章节结构、错别字与排版特征、统一模板与规范条文来源、文件形成过程 |
| P-01 `LOCAL_RELATION_CLUE` | 用户提供本地关联关系线索 | 线索原件、合法来源、登记/人员/账户资料及主体核验 |
| P-02 `PERSON_OVERLAP` | 法定代表人、联系人、联系电话或项目经理等人员字段跨投标人出现相同值 | 登记信息、授权委托、项目人员资料、联系电话归属和身份核验 |
| P-03 `KINSHIP_RELATION` | 本地关联线索中涉及夫妻、亲属、兄弟姐妹等关系，且至少一方匹配已扫描投标人 | 合法登记/户籍/婚姻等资料、线索原件和主体核验 |
| P-04 `PERSON_TABLE_OVERLAP` | relations 文件中的「人员+企业(+职务)」长表（企查查等公示导出风格）里，同一人任职记录命中至少两家投标人名称（精确匹配）；配对表行不适用本规则 | 工商登记、社保与劳动合同等有权资料，导出文件原件和人员真实归属核验 |

当前已启用的规则编号为 F-01~F-07、E-01~E-02、S-01~S-05、P-01~P-04；F-08~F-10
仍未列入启用规则。每条新增规则均从 `review_directory` 主流程产生，信号固定为
`auto_conclusion=false`，整份结果固定为 `manual_review_required=true`。

报价识别中，XLSX 原生数值按单元格类型解析，不先转成文本；PDF 读取边界如上；`招标控制价`、`最高限价`、`控制价`单独标记为 `kind=control`，不作为投标人的
`primary_quote`；主报价优先选择含税/显式投标总价，同一优先级出现不同金额时不猜测并返回空值。
金额文本支持如 `1.234,56` 和 `1,234.56` 的混合分隔格式；单个点后三位且非零开头（如 `123.456`）存在口径歧义，跳过并提示核对；报价标签后出现多个未标注数字时保守跳过，
不跨列猜测税率、数量或其他金额的字段归属。E-02 证据只保留脱敏账号，完整账号不写入公开结果；
报价、清单和关联线索的公开原文字段也会按账户字段做脱敏处理，原始文件保持不变。

阈值是可解释的初筛参数，不是法定标准。单一 IP、MAC、作者、文件名、联系人、文本相似、
报价接近或本地线索都不能单独作出法律判断。

F-04 仅对同时具备明细名称、单位和规格/项目特征的项目建立比较键；缺少任一口径字段的明细会
标记为 `INSUFFICIENT_DATA`，保留在输出中但不按名称自动合并，也不触发该规则。输入扫描会跳过并记录
符号链接，并受单文件、总文件数、总字节数及 XLSX ZIP 成员/声明解压大小限制；超过限制时报告标记为
扫描不完整，不能把未纳入部分理解为未发现风险。

## 法律边界

设计背景为国家现行《招标投标法》《招标投标法实施条例》、国家发展改革委令第20号、
发改法规规〔2022〕1117号，以及浙江工程建设场景下的浙政发〔2024〕17号和杭州杭建市
〔2020〕190号。官方链接见 [README](../README.md) 的“法律与适用范围边界”。

要点仅用于决定“留什么证、复核什么”：实施条例第34条的单位负责人同一或控股/管理关系边界，
第39—42条关于协商报价、约定中标/放弃、同一编制或办理、文件异常一致/报价规律性差异、
文件混装、保证金同账户、招标人与投标人串通及借资质/虚假资料等规则，以及第51条评标相关
程序要求，都必须结合适用范围、完整事实证据和法定程序；电子系统中的签名、来源、
时间、网络地址、归档、下载上传和撤回记录要以平台原始记录为准。浙江17号意见涉及的机器码、
文件创建标识码、IP、电子保函账户等，也只能作为结合证据的线索。

政府采购另有[财政部令第87号](https://tfs.mof.gov.cn/caizhengbuling/201707/t20170718_2652603.htm)
和[浙财采监〔2025〕2号（杭州财政官方页面）](https://czj.hangzhou.gov.cn/art/2025/5/13/art_1655737_59023282.html)
的适用边界，仅在项目标记为政府采购且招标文件载明时启用，不直接外推到一般工程建设。

## 测试资料状态

截至 2026-09-08，暂无已确认的“同一项目、多家单位投标”真实测试资料。用户已明确要求：

- 不打开、不读取、不复制其本机候选资料；
- 不把演示/合成命名资料当作真实投标业务证据；
- 含 `.xls` 的资料组不纳入当前解析范围；
- 后续若有权限人员提供脱敏资料，只做格式烟测或经确认的离线回放，并在报告中保留来源、
  范围、版本和脱敏状态。

因此，当前测试只使用运行时构造的合成内容，不能证明程序已在真实同项目投标文件上验证。
当前全量自动化测试结果以 `docs/PROGRESS.md` 最新记录为准；离线规则专项包含 E-02 和金额字段歧义回归测试。
新增集成测试使用合成 CSV、XLSX、JSON、PDF 与 `relations.csv`，已从 `review_directory` 主流程同时产生
F-05、F-06、F-07、E-02、S-04、P-02、P-03、P-04，并核验控制价 `kind`、账户脱敏和全部信号的人工复核边界。
